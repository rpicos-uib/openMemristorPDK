Introduction to FOSS

Every program in this guide is free and open-source software. Meet them one by one: what each does, who makes it, how to install it. Then let openPDKcreator's Tools tab check them for you. You only ever need to click whatever is inside the red box, or type exactly what is in a black box.

Before you start

What is FOSS?

FOSS means Free and Open-Source Software. "Free" as in freedom, not only as in price: the program's source code, the text it is made from, is public, and its license lets anyone use it, read it, change it and share it.

Free to use

No licence fee, no account, no limit on how many computers. A school can install it in every classroom.

Open to read

Every line is on the internet, usually on GitHub. If you want to know exactly how a simulator computes something, you can look.

Free to change and share

Fix a bug, add a feature, give your version to a friend. openMemristorPDK itself is a change you can make: it's all text files.

Made by a community

Universities, companies and volunteers around the world write these programs together, and many have been improved for decades.

?

Why it matters for chips

For a long time, designing a chip needed very expensive commercial programs and a PDK the factory only gave out under a secrecy contract. Since about 2020 some factories have published open PDKs (SkyWater, GlobalFoundries and IHP, whose PDK this guide uses), and open programs can now take a design all the way to a layout the factory can build. Students, schools and small teams can design real chips.

Licenses in one minuteEvery FOSS program comes with a license, its rules. The two big families: GPL (if you share a changed version, you must share its source code too) and permissive licenses such as Apache, BSD and ISC (do almost anything, just keep the credit). openPDKcreator and openMemristorPDK use Apache 2.0.

Git

Downloads projects and remembers every version of them.

Git keeps the whole history of a folder of files: every change, who made it and when, so you can always go back. GitHub is a website that stores Git projects for everyone to see; git clone downloads one to your computer. openPDKcreator, the memristor PDK and the container's launcher all live on GitHub.

Podman

Runs containers: a ready-made computer inside your computer.

A container is a complete, packed Linux system with programs already installed and set up. Podman downloads it and runs it, kept apart from the rest of your laptop. Installing forty chip-design programs one by one would take days; with a container it is one download. Podman does the same job as the better-known Docker, but needs no administrator program running in the background.

The toolbox: dozens of chip-design programs in one container.

openPDKcreator

Build and explore a PDK in one window.

A window for looking inside a PDK and for building a new one: its layers, design rules, devices, symbols, models and layouts. Its Library Manager lists every cell and opens each view in the right program (a schematic in xschem, a layout in KLayout). It compiles Verilog-A models by itself when it starts, and its Tools tab checks the programs on this page (see openPDKcreator's Tools tab below). openMemristorPDK was built with it.

xschem

Draw circuits as schematics.

A schematic editor: you place symbols (a memristor, a voltage source, a transistor) and connect them with wires. Press Netlist and it writes the circuit as text for the simulator; press Simulate and it runs ngspice and shows the result.

ngspice

The circuit simulator: works out every voltage and current.

Give it a circuit (a netlist) and it computes how the voltages and currents change over time: the pinched hysteresis loop, the write and read currents of a bit. It grew out of SPICE, written at the University of California, Berkeley, in the 1970s, the program every circuit simulator since is based on. It can load models compiled by OpenVAF, which is how it simulates our memristors.

OpenVAF

Turns a Verilog-A model into something ngspice can run.

Our memristor models are written in Verilog-A, a language for writing a device's equations (the .va files). OpenVAF compiles a .va file into an .osdi file that ngspice loads. openPDKcreator runs it for you every time it starts. The container has OpenVAF-Reloaded, the version the community keeps up to date.

KLayout

Look at chip layouts and check them.

A layout is the drawing the factory builds from: coloured shapes, one colour per layer of material, stored in a GDS file. KLayout opens these files, even huge ones, fast. It also runs the DRC (design rule check): a script that measures every shape and complains when something is too small or too close.

The classic layout editor, which also reads circuits back out of layouts.

Netgen

Checks that the layout is the same circuit as the schematic.

This check is called LVS, layout versus schematic. Netgen takes the netlist Magic extracted from the layout and the netlist from the schematic, and compares them device by device and wire by wire. If one wire is missing in the layout, LVS finds it before the factory does.

Icarus Verilog

Simulates digital circuits written in Verilog.

Verilog describes digital circuits as text: registers, logic, clocks. Icarus Verilog (iverilog) compiles that text and runs it, writing every signal's ones and zeros over time into a .vcd file. It is quick: no voltages, just bits.

Yosys

Turns Verilog into real logic gates.

This step is called synthesis. Yosys reads a Verilog description and builds the same behaviour out of the logic gates a factory offers (here IHP's standard cells: NAND, flip-flops and so on), then counts them and their area.

OpenROAD and LibreLane

From logic gates to a finished chip layout, automatically.

OpenROAD places the gates on the chip, builds the clock wiring, routes every wire and checks the timing (with OpenSTA). LibreLane is the recipe that runs the whole chain in order: Yosys, OpenROAD, then the Magic and KLayout DRC and the Netgen LVS, and collects the reports. One command goes from Verilog to a GDS file the factory could build. LibreLane continues OpenLane 2.

Hands on · about 5 minutes

openPDKcreator's Tools tab

openPDKcreator can check all these programs for you: which ones are installed, which version, where, and how to install the missing ones. It can also start any of them. Do this part after Install from scratch, with openPDKcreator open (steps 1–3 of Your first simulation).

1

Open Settings

Click the Settings tab at the top of openPDKcreator.

2

Open the Tools tab

Click Tools, the second tab under Settings.

3

Read the summary

Wait a few seconds while it checks every program, then read the line at the top.

What you see16/16 tool(s) found: inside the container every program is there. Below, one row per program: its short name (Id), its job (Category), whether a PDK flow needs it (Required), Status, the Version it reported and the Path of the program file. OpenLane says superseded by librelane: LibreLane replaced it, so it isn't needed.
4

Click a program

Click the ngspice row (1). Its card appears on the right (2).

The cardWhat the program is for, which part of a PDK it works with, where it was found and its version. Then how to install it on this kind of Linux (here sudo apt install ngspice), notes worth knowing, and its website. openPDKcreator only shows install commands: it never installs anything by itself.
5

Start a program from here

Click the klayout row (1), then Launch Selected (2).

6

KLayout opens

KLayout opens, empty and ready, with our PDK's layer colours set up. Close it with its ✕.

Same set-up as the Library ManagerLaunch Selected starts each program the way the Library Manager does: KLayout with this PDK's layers, xschem with this PDK's symbols, Magic with its technology file.
7

After installing something: Recheck

If you install a program while openPDKcreator is open, click Recheck to look again.

A program says "missing"?That happens when you run openPDKcreator outside the container. Click its row, copy the install command from its card, run it in a terminal on your laptop, then click Recheck. Rows with Required: no are optional: you can work without them.
