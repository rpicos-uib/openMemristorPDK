Part 1 · the idea

One memristor, one bit

Computers store everything as bits, zeros and ones. A memristor can hold a bit without any power, because its resistance stays where you left it. That is the whole "digital side" of a memristor: it is a tiny memory cell that keeps its data with the power off, the idea behind RRAM (resistive RAM).

1

Bit 0 and bit 1

bit 1
The memristor is on: low resistance (Ron), a lot of current flows.
bit 0
The memristor is off: high resistance (Roff), very little current flows.
write 1 (SET)
A short, big positive voltage pulse switches it on.
write 0 (RESET)
A short, big negative pulse switches it off.
read
A small voltage, too small to switch anything. Measure the current: big means 1, small means 0.
Why the HfO₂ memristorThe Au/HfO₂/Al memristor from Add a new device only changes above +0.8 V or below −0.6 V. So a 0.2 V read can never change the bit by accident.

What happened 0.7 V is below the +0.8 V threshold, so the memristor never switched on. It stayed a plain 50 kΩ resistor. 14 µA during the write is just Ohm's law: 0.7 V ÷ 50 000 Ω. Read 2 is 4 µA, the same as read 1.

Why this mattersReal memory chips must write with enough voltage, but they also must read with a small enough one. The gap between the two (0.2 V for reading, more than 0.8 V for writing) is what makes the memory safe.

Part 4 · about 10 minutes

Write a pattern into a crossbar

One bit isn't much. Put memristors where rows and columns of wire cross and you get a crossbar: 4 bits in a 2 × 2 grid, 16 in 4 × 4. You'll write the pattern 1 0 / 0 1 into four HfO₂ memristors, read it back, and then see how a careless write ruins it.

27

How you pick one cell

Each memristor sits between one column wire (its BE) and one row wire (its TE). It feels the column voltage minus the row voltage. To write one cell with 1.2 V, the testbench shares the voltage: +0.6 V on its column and −0.6 V on its row. All other wires stay at 0 V.

Writing cell 11ColumnRowIt feelsSwitches?
cell 11 (the one we want)+0.6 V−0.6 V1.2 Vyes
cell 12 (same row)0 V−0.6 V0.6 Vno, below 0.8 V
cell 21 (same column)+0.6 V0 V0.6 Vno, below 0.8 V
cell 220 V0 V0 Vno
The trickThe neighbours only get half the write voltage, and half is below the +0.8 V threshold. That is why a memristor with a clear threshold, like the HfO₂ one, is good for memories.

Why ground the other wires?During a read, the unused row and column sit at 0 V. If they were left unconnected, current could sneak through the other memristors (column → cell → other row → cell → …) and make a 0 look like a 1. Real chips fight these sneak paths by grounding wires like here, or by adding a transistor to every cell (1T1R).

What went wrong

ngspice agrees: 400 µA everywhere.

Write disturb Writing cell 11 put 1.2 V on column 1. Cell 21 is on the same column, and its row was at 0 V, so it felt the full 1.2 V too and switched on. Writing cell 22 did the same to cell 12. A write that only looks at the cell you want can change its neighbours: sharing the voltage between column and row is what keeps them safe.
Try itcolpart = 0.75 puts 0.9 V on the column: just above the threshold, and the neighbours on the same column get written too. Every value between 0.34 and 0.66 keeps both neighbours below 0.8 V.

Part 5 · about 10 minutes

A digital twin in Verilog

Digital designers don't simulate currents: a chip has millions of bits, far too many for ngspice. They use a digital twin, a short description in Verilog that only says what the memristor does with ones and zeros. You'll simulate one with Icarus Verilog and look at the result in GTKWave.

48

The twin

This is the whole twin, in openMemristorPDK/digital/memristor_bit/memristor_bit.v. Nothing to type: it's already there.

memristor_bit.vVerilog
// memristor_bit.v -- a digital twin of the Au/HfO2/Al memristor used
// as a 1-bit memory. No voltages or currents: only what a digital
// designer needs to know about it.
//
//   set   = 1 : a write pulse above +0.8 V -> the bit becomes 1
//   reset = 1 : a write pulse below -0.6 V -> the bit becomes 0
//   read  = 1 : a small 0.2 V read         -> q shows the bit
//
// A write only works if its pulse lasts at least T_SWITCH (15 ns, about
// what the ngspice simulation of the real model needs). When nothing
// happens the bit stays where it is: no power needed.
`timescale 1ns/1ps

module memristor_bit #(parameter T_SWITCH = 15) (
  input  wire set,
  input  wire reset,
  input  wire read,
  output wire q
);
  reg stored = 1'b0;   // x0 = 0: the memristor starts off

  // A SET pulse: wait T_SWITCH, then switch on if the pulse is still there.
  always @(posedge set) begin
    #(T_SWITCH);
    if (set) stored = 1'b1;
  end

  // A RESET pulse: the same, switching off.
  always @(posedge reset) begin
    #(T_SWITCH);
    if (reset) stored = 1'b0;
  end

  // While reading, q shows the bit; otherwise q is disconnected (z).
  assign q = read ? stored : 1'bz;
endmodule
input, output
The wires of the block: three going in (set, reset, read) and one coming out (q). Each is 0 or 1.
reg stored
The bit inside the memristor. It starts at 0, like x0=0 in xschem.
always @(posedge set)
"Every time set goes from 0 to 1". Then #(T_SWITCH) waits 15 ns, and the bit becomes 1 only if set is still on: a pulse that is too short does nothing.
assign q = read ? stored : 1'bz
While reading, q shows the bit. Otherwise it is z: not connected, neither 0 nor 1.
The testA second file, memristor_bit_tb.v, does the same as the xschem testbench of part 2: read, write 1, read, write 0, read. Then one more write 1 that lasts only 5 ns, and a last read.

Part 6 · what digital tools need

The memristor seen by digital tools

Digital chip tools don't simulate currents. They work with blocks that have pins, a size and a speed. For them a memristor is a black box with two pins, BE and TE. The PDK already has every file they would ask for, made with the Library Manager (see the second slide deck, digital_aspects.tex).

Why so empty?A memristor has no clock and no logic function, so Liberty's usual "delay from input to output" doesn't describe it. Real memory chips solve this by wrapping the memristors in a memory macro (array + the circuits that write and read it), and only the macro gets real Verilog and Liberty views.

Glossary

Words you'll meet

RRAM
Resistive RAM: memory that stores bits as the resistance of memristors.
non-volatile
Keeps its data without power (like a USB stick, unlike a computer's main RAM).
Verilog
A language to describe digital circuits as text.
synthesis
Turning a Verilog description into real logic gates (Yosys does this).
place and route
Deciding where every block goes on the chip and drawing the wires between them (OpenROAD, LibreLane).
Liberty (.lib)
A data sheet for tools: how fast, how much power, which pins.
LEF
A block's outline and pin positions, without the inside details.
1T1R
One transistor, one resistor (memristor): the usual RRAM bit-cell.
digital twin
A simple digital model that behaves like the real device for ones and zeros, without the physics.
waveform
A picture of signals changing over time, as GTKWave draws them.
crossbar
A grid of row and column wires with a memristor at every crossing: one bit per crossing.
write disturb
Writing one cell changes a neighbour by accident, because the neighbour got too much voltage.
sneak path
An unwanted route for current through neighbouring cells of a crossbar.
