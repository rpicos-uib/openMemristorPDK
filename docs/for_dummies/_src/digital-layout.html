About 10 minutes

Step by step

The 65 gates of the controller are only a list so far. Place and route decides where each gate sits on the chip and draws every wire between them, then checks the result. LibreLane does the whole job in one command, using IHP's standard cells.

1

What LibreLane does

synthesis
Verilog to gates, as in the previous part (Yosys).
floorplan
Choose the size of the chip and lay out rows where gates can sit, plus the power wires.
placement
Put every gate in a row, close to the gates it talks to.
clock tree
Add buffers so the clock reaches all flip-flops at the same time.
routing
Draw every wire on the metal layers, without shorts.
checks
Design rules (DRC), layout against netlist (LVS), antennas, and timing: is the circuit fast enough for a 10 ns clock?

All of that from a five-line file, mem_ctrl.json, in the same folder as the controller:

mem_ctrl.jsonLibreLane configuration
{
    "DESIGN_NAME": "mem_ctrl",
    "VERILOG_FILES": "dir::mem_ctrl.v",
    "CLOCK_PORT": "clk",
    "CLOCK_PERIOD": 10
}
DESIGN_NAME
The Verilog module to build.
VERILOG_FILES
Where it is; dir:: means "next to this file".
CLOCK_PORT, CLOCK_PERIOD
The clock input and its period: 10 ns, the same 100 MHz clock as the simulation.
Which PDK?The container is set up for IHP SG13G2, so LibreLane uses it without being told. See Add IHP's PDK.
2

Open a terminal

In the container desktop, click the terminal icon in the bottom panel.

3

Go to the folder

Go to the controller's folder and look at the configuration:

$ cd openMemristorPDK/digital/memory2x2
$ cat mem_ctrl.json
4

Run LibreLane

Start it. A progress bar at the bottom counts its 80 stages; it takes about two minutes.

$ make layout
What scrolls byEach stage prints what it does. Here, stage 35 is building the clock tree with IHP's clock buffers (sg13g2_buf_8, ...).
5

It's done

The prompt comes back. The last lines are yellow WARNINGs.

Warnings are fine hereThey say some settings were left at their defaults (timing constraints, power-grid analysis...). For a practice design that's what we want. The real verdict is in the next step.
6

The results

make report prints the main results of the run in plain words.

$ make report
Chip size
About 67 × 67 µm: the controller fits in a square smaller than the thickness of a hair.
Cells placed
137: the 65 gates, plus buffers added for the clock and for speed, and filler cells.
Design rules
No shapes too thin or too close: the factory could build it.
Layout vs. netlist
The drawn wires connect exactly the gates the netlist says.
Timing
Even in IHP's slowest corner (1.08 V, 125 °C) every signal arrives 5.6 ns before the next clock tick.
7

Open the layout

make view opens the finished chip in KLayout, with IHP's layers. A Tip asks how to show the cells: click Yes.

$ make view
8

Make it bigger

Click the maximize button of the KLayout window.

9

The chip

This is the controller, ready to build.

How to read it The dashed purple square is the edge of the chip. Inside, the gates sit in horizontal rows, each labelled with its IHP name. The coloured lines are wires on different metal layers (the Layers list on the right). The two wide vertical stripes carry power. Around the edge are the pins: clk, start, op, addr, data_out, busy and the set/reset/read wires to the memristors.
10

Zoom in

Point at the cells and turn the mouse wheel forward to zoom in. Now you can read the gate names, like the flip-flop sg13g2_dfrbpq_1 (boxed).

11

Close KLayout

Click the X at the top-right of the KLayout window.

12

Close the terminal

If you want, make clean deletes the run (make layout makes it again). Then close the terminal.

$ make clean
$ exit
